## 1. 진단

### 1.1 보안 (즉시)

- **AWS 액세스 키 평문 노출 (치명)** — 모든 페이지의 `__meteor_runtime_config__`에 `accessKeyId(AKIA…)`와 `secretAccessKey`가 그대로 실려 나온다. 브라우저 소스 보기만으로 취득 가능하며, 같은 번들에 AWS SDK 전체가 포함되어 S3 버킷(`prj-access9.files`)에 바로 쓸 수 있는 상태. 같은 자리에 내부 AI API 키도 하드코딩되어 있다.
  **조치: 키 즉시 비활성화·회전 → 업로드는 서버 발급 presigned URL로 전환 → 노출 기간 S3/IAM 접근 로그 점검.**
- **운영 사이트가 스테이징 AI 서버 호출 (치명)** — AI baseUrl이 `…-rag-staging.up.railway.app`. 운영 트래픽이 스테이징 인스턴스에 의존.
- **보안 헤더 없음 (중대)** — CSP / X-Frame-Options / X-Content-Type-Options / Referrer-Policy 모두 미설정. (HSTS는 적용됨)

### 1.2 전환 (방문자가 고객이 되지 못하는 구간)

- **상품 상세에 구매 경로가 없음 (치명)** — 상세 페이지 높이 17,800px 중 담기·견적요청·문의 버튼 0개. 규격별 단가표(5행)는 클릭 불가. "견적 조건", "판매자 특이사항"은 `-`로 비어 있음.
- **AI 검색이 백지 반환 (치명)** — 헤더가 "AI에게 바로 물어보려면 `?`를 붙여보세요"라고 안내하지만, 실제 질문 시 헤더/푸터만 남은 빈 화면. 오류·안내 없음.
- **핵심 기능 전면 로그인 벽 (치명)** — `/solutionPosts`, `/ai/chats/new`, `/carts`, "솔루션 의뢰" 모두 `/sign?tab=i`로 리다이렉트. 로그인 화면에 가입 이유 설명 0줄.
- **가장 잘 만든 화면이 숨어 있음 (중대)** — 현장별 실시간 투입비/카테고리별 집계/처리 대기 건수를 보여주는 화면이 이미 존재하나, 진입점은 우하단 회색 플로팅 버튼 "현황" 하나이고 주소는 `/turorial/overview`(오타). 홈에서 한 번도 언급되지 않는다.

### 1.3 모바일 (치명)

- iPhone 390px 접속 시 문서 폭이 1,028px로 고정(상세 1,024px). 반응형이 아니라 데스크톱 축소본. 로고·"발주서"·푸터가 좌우로 잘림. 정작 앱 설치 유도 배너는 이 화면에 존재.

### 1.4 정보구조

- **솔루션·상품·판매사가 동일한 카드 그리드 (중대)** — 세 개념의 차이를 설명하는 문구가 화면에 없음. 비선택 탭은 회색이라 비활성처럼 보임.

- **카테고리/정렬/탭이 URL에 반영되지 않음 (중대)** — 무엇을 눌러도 `/home` 고정. 링크 공유 불가, 뒤로가기 무의미, 색인 대상 카테고리 페이지 부재.
- **검색이 목록만 반환 (중대)** — "안전모" 4건. 총 건수·필터·정렬 없음. 0건 시 "검색결과가 없습니다." 한 줄.

## 2. 개편 방향

### 2.1 포지셔닝: "자재를 파는 곳" → "현장 투입비를 관리하는 곳"

지금의 홈은 상품 그리드라서 일반 자재 도매몰과 가격으로 비교된다. 반면 대체재가 없는 자산은 **현장별 투입비 현황**(예상/확정 금액, 카테고리별 투입비, 결재·발주·운송·거래내역서 대기 건수)이다. 홈의 첫 문장을 "자재를 사면 현장 투입비가 저절로 정리된다"로 바꾸고, 상품은 그 약속을 실행하는 수단으로 배치한다.

### 2.2 세 축 분리

- **솔루션** — 공정·위험 상황(문제)이 제목. 자재 조합·규격·시공 유의사항이 답. 검색 유입과 상담의 진입점.
- **상품** — 규격·단가·재고로 고르는 카탈로그. 반복 구매·비교.
- **현장** — 로그인 후 업무 도구(발주서·투입비·거래내역·정산). 재방문과 고착.

카드 형태·색·정보 구성을 셋으로 분리한다. A1~AL 카테고리 색은 이미 현황 화면에 존재하므로 이를 사이트 전체 디자인 시스템의 뼈대로 승격한다.

### 2.3 로그인 벽 후퇴

솔루션·상품·검색·AI 질문은 비로그인 공개. 로그인은 담기 이후 발주·견적 직전에 요구. 가입 화면에 얻는 것 3줄 + 역할 선택(구매사/판매사)을 둔다.

## 4. 기술 개편

- **공개 페이지 분리 및 서버 렌더링** — 홈·솔루션·카테고리·상품 상세·판매사·소개/사례를 Next.js 등으로 분리해 정적/서버 렌더링. 색인과 첫 화면 지연이 동시에 해결됨. 로그인 이후 업무 화면은 기존 Meteor 앱 유지 후 점진 이관.
- **번들** — 2.7MB 단일 번들을 라우트 단위로 분할, 클라이언트에 불필요한 AWS SDK 전체 포함 제거, 폰트 1벌 서브셋. 목표: 첫 화면 전송 300KB 이하.
- **보안** — AWS 키 폐기·회전, presigned URL 업로드, 클라이언트 설정에서 비밀값 제거, AI API 운영 인스턴스 분리 및 서버 프록시화, nginx 보안 헤더 추가.
- **URL·색인** — 상태를 URL에 반영, 한글 경로 이중 인코딩 수정(또는 영문 slug), robots.txt·sitemap.xml 생성, canonical 지정(www/non-www 정리), 없는 주소는 실제 404 반환.
- **마크업** — 이동은 `<a href>`로(JS 클릭 병행), 페이지당 h1 하나, header/nav/main/footer 도입, 이미지 alt, `<html lang="ko">`.
- **이미지** — 상세 이미지 WebP 변환·리사이즈·지연 로드.
- **운영 규칙** — 빈 값이면 섹션 숨김, 상품명 내부 메모 금지, 상품 0개 판매사 비노출을 데이터 검증 규칙으로 고정.

## 5. 실행 순서

### 0차 — 이번 주 (개편과 무관하게 즉시)
- AWS 키 폐기·회전, 접근 로그 점검, presigned URL 전환
- AI API 운영 인스턴스 분리, AI 검색 백지 수정(최소한 실패 메시지)
- 상품·솔루션 상세에 담기/견적요청 버튼 추가
- "시즌 상품 숨김 처리" 등 상품명 정리, 빈 값 섹션 숨김
- 잘린 문구("로그인하고"), `turorial` 오타, 약관 회사명 표기 수정
- 회사 소개 페이지 작성, 공지 갱신, FAQ 10문항

### 1차 — 2~4주
- 모바일 반응형 전환(헤더·그리드·상세·검색)
- URL 설계 적용(카테고리·정렬·페이지·검색어)
- 검색 개선: 건수·필터·정렬, 0건 대체 제안
- 홈 1차 개편(가치제안 + 상황별 진입 + 현황 미리보기), 여백 제거
- 이미지·폰트 최적화, 보안 헤더 적용

### 2차 — 1~2개월
- 공개 페이지 서버 렌더링 분리, 번들 분할
- 솔루션·상품 상세 재설계(견적 패널, 규격별 담기, 갤러리)
- 디자인 시스템 1.0(카테고리 색 체계·카드 3종·상태 배지)
- 판매사 영역 재구성, 도입 사례 페이지 신설
- 접근성 기본(시맨틱·alt·키보드·대비)

### 3차 — 3개월 이후
- 현황(대시보드)을 로그인 첫 화면으로 승격, 업무 흐름 재설계
- 발주–운송–거래내역–정산 UX 정리, 알림
- AI 상담 정식화(솔루션·상품 근거 제시 → 견적 연결)
- 판매사 셀프 온보딩·상품 등록 도구
