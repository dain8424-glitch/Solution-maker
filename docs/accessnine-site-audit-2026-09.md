## 1. 진단

### 1.1 보안 (즉시)

- **AWS 액세스 키 평문 노출 (치명)** — 모든 페이지의 `__meteor_runtime_config__`에 `accessKeyId(AKIA…)`와 `secretAccessKey`가 그대로 실려 나온다. 브라우저 소스 보기만으로 취득 가능하며, 같은 번들에 AWS SDK 전체가 포함되어 S3 버킷(`prj-access9.files`)에 바로 쓸 수 있는 상태. 같은 자리에 내부 AI API 키도 하드코딩되어 있다.
  **조치: 키 즉시 비활성화·회전 → 업로드는 서버 발급 presigned URL로 전환 → 노출 기간 S3/IAM 접근 로그 점검.**
- **운영 사이트가 스테이징 AI 서버 호출 (치명)** — AI baseUrl이 `…-rag-staging.up.railway.app`. 운영 트래픽이 스테이징 인스턴스에 의존.
- **보안 헤더 없음 (중대)** — CSP / X-Frame-Options / X-Content-Type-Options / Referrer-Policy 모두 미설정. (HSTS는 적용됨)

### 1.2 전환 (방문자가 고객이 되지 못하는 구간)

- **비로그인 상태에서 구매 경로가 보이지 않음 (치명)** — 비로그인 상세 페이지(높이 17,800px)에 담기·견적요청·문의 버튼 0개. 규격별 단가표(5행)는 클릭 불가. "견적 조건", "판매자 특이사항"은 `-`로 비어 있음. **구매사 계정으로 로그인하면 "발주서에 추가"·"구성자재로 발주" 버튼이 정상 노출됨** → 기능 부재가 아니라 신규 방문자에게만 행동 신호가 0인 문제.

## 1.8 로그인 안쪽 (판매사관리자 계정 확인분)

안쪽에는 실제로 돌아가는 업무 시스템이 있다. 최근 한 달 발주 21건, 판매 20,050,000원 / 임대 500,000원, 수량 1,483, 구매사 10여 곳의 실데이터가 흐른다. 문제는 이 자산이 밖에서 전혀 보이지 않는다는 것, 그리고 안쪽도 결함이 있다는 것.

- **ag-Grid Enterprise 라이선스 미등록 (치명)** — 발주 내역(`/orders`), 거래내역서(`/invoices`), 파트너 관리(`/ecpPartners/manage`), 권한 목록(`/mymembers`), 솔루션 의뢰내역(`/solutionPosts`) 등 표가 있는 거의 모든 업무 화면에 `For Trial Use Only` 워터마크가 표시된다. 번들에 라이선스 검증 실패 시 콘솔 오류 출력 + 워터마크 설정 분기가 포함돼 있다. 구매사에게 노출되는 화면이며 상용 라이선스 미구매는 법적 리스크. → 라이선스 구매·키 등록 또는 Community 기능으로 대체.
- **AI 실시간 응답 실패 (치명)** — 새 채팅에 질문 전송 시 60초 이상 무응답(타이핑 표시 점 하나만), 오류·재시도 안내 없음. 반면 과거 대화(`/ai/chats/{id}`)는 정상 저장되고 답변 품질도 양호. UI·데이터는 정상이고 실시간 응답 경로만 죽은 상태 — 비로그인 "?" 검색 백지와 동일 원인(스테이징 RAG 서버)으로 추정.
- **채팅 이력 = 고객 리서치 자료 (기회)** — 실제 질문들: "철근 제작~가공~배근 솔루션 만들어줘"(공정 단위 묶음), "매립형 안전걸이 대량 구매 가능해?"(대량 견적), "운송장은 엑셀로 다운받을 수 없어?"(내보내기), "판매사한테 1:1 문의 할 수 있어?"(판매사 직접 문의), "시스템동바리 대체할 수 있는 자재 알려줘"(대체재 비교). 개편 우선순위 판단에 직접 활용 가능.
- **"권한 변경 필요"는 아이콘만 클릭됨 (개선)** — 판매사 권한으로 상품을 보면 구매 버튼 자리에 `권한 변경 필요` 라벨이 표시된다. 위쪽 아이콘 클릭 시 "본사관리자 권한으로 변경을 하시겠습니까?" 모달이 뜨고 확인하면 즉시 구매사로 전환된다(동작 정상). 다만 **라벨 텍스트는 클릭되지 않고 24px 아이콘만 히트 영역**이라, 라벨을 누른 사용자는 고장으로 인식하게 된다. 라벨 전체를 버튼화하면 해결.
- **사용법 안내가 로그인하면 사라짐 (중대)** — `/turorial/overview`, `/turorial/order`, `/turorial/solution` 세 페이지 모두 로그인 상태에서는 헤더만 남은 백지. 비로그인일 때만 기능 설명이 렌더링됨(그마저 버튼 문구가 "로그인하고"에서 끊김). 실제 사용자는 사용법 안내를 볼 수 없음.
- **업무 화면도 비반응형 (중대)** — `/orders`를 iPhone 390px에서 열면 문서 폭 1,032px 고정.
- **플로팅 버튼이 핵심 수치를 가림 (중대)** — 발주 내역의 "수량 계 1,483", "총 금액 합계 20,550,0…", "20개씩 보기" 선택이 AI 채팅/솔루션 의뢰/현황 버튼에 가려짐.
- **주 메뉴 16개가 hover 전용 (중대)** — MY 내역(8) + 더보기(8)가 마우스 오버로만 열리고 클릭·터치 무반응 → 태블릿/모바일 접근 불가. 라벨도 시스템 언어("서류별 내역", "나의 권한 목록", "내 상품의 파트너 관리").
- **작성/조회 분리 (개선)** — 상단 바(운송장 작성·반출입력·거래내역서 작성)와 MY 내역(운송장·운송 내역·반출 내역·거래내역서)에 같은 업무가 위치로 갈라져 있음. 업무 단위(운송/반출/정산)로 묶고 그 안에서 작성·조회를 나눌 것.
- **현황 빈 상태 (개선)** — 실제 `/overview`는 카테고리 전 항목 0원. 빈 상태 안내 없음, `NN 카테고리 없음` 내부 코드 노출.
- **영문 UI 잔존 (개선)** — 표 페이지네이션이 `1 to 20 of 21 · Page 1 of 2`.
- **미완성 데이터 (개선)** — QR코드 관리 상품 목록의 '기본 설명' 전부 "없음", 관리코드 열 공란.
- **구성원 연락처 노출 (개선)** — 판매사 관리 화면에 구성원 이름·휴대폰번호가 표로 표시. 마스킹 및 열람 권한 최소화 검토 필요.

### 1.9 구매사(본사관리자) 흐름

구매 흐름은 이미 제대로 구현돼 있다. 상품 상세에 "발주서에 추가"(주황) · "구성자재로 발주"(네이비) 두 CTA가 크게 배치되고, 발주서는 단순 장바구니가 아니라 **이름을 붙여 재사용하는 발주서**다(저장된 예: `기본발주서`, `기둥선타설`). 공정별 발주서를 만들어 반복 발주하는 현장 방식에 부합하는 좋은 모델.

- **발주 버튼이 AI 채팅 플로팅 버튼에 가려짐 (치명)** — 발주서 화면의 주황색 "발주" 버튼(결제 확정에 해당) 오른쪽 절반이 AI 채팅 버튼에 덮인다. 총 발주금액 합계도 같은 자리에서 잘림. 플로팅 버튼 겹침 사례 중 최악.
- **현황 기본 탭이 백지 (중대)** — 구매사로 `/overview` 진입 시 기본 선택이 "전월 통계"인데 현장 칩 외 본문이 완전히 비어 있음. 실제 데이터(26년 9월분 투입현황, 예상·확정 금액, 결재/발주/운송/거래내역서 대기 건수)는 "당월 실시간" 탭에 존재. 기본 탭 변경만으로 개선 가능.
- **구매사 메뉴 17개도 hover 전용 (중대)** — MY 내역(발주 내역·결재서·운송장·운송 내역·반출 내역·거래내역서·투입 내역), 더보기(프로필 설정·권한 요청·나의 권한 목록·파트너상품 관리·본사&현장 관리·즐겨찾기 관리·좋아요한 목록·로그아웃). 터치 기기에서 접근 불가.
- **발주서 세부 완성도 (개선)** — 라인 삭제가 작은 `[×]` 아이콘 하나(오조작 위험), 품목 추가 빈 카드의 회색 박스가 이미지 로딩 실패처럼 보임, 도착지 안내 문구 띄어쓰기 오류("현장 지정이 필요한경우"), 담당자 이름에 "액세스나인전직원" 잔존, "규격을 꼭 입력해야만 발주됩니다" 경고와 금액 합계가 한 덩어리로 붙어 있어 둘 다 인지되지 않음.


### 개편안에 미치는 영향

포지셔닝 전환("자재 판매 → 현장 투입비 관리")의 근거가 강해진다. 발주·운송·반출·거래내역서·투입비로 이어지는 업무 시스템과 품질 좋은 AI 답변이 이미 존재하는데, 공개 영역에서는 그 어느 것도 보이지 않는다. 개편은 없는 것을 지어내는 일이 아니라 이미 있는 것을 드러내는 일이다.

0차(즉시) 항목에 두 가지 추가: **ag-Grid 라이선스 등록**, **AI 응답 경로 복구**.

## 2. 개편 방향

### 2.1 포지셔닝: "자재를 파는 곳" → "현장 투입비를 관리하는 곳"

지금의 홈은 상품 그리드라서 일반 자재 도매몰과 가격으로 비교된다. 반면 대체재가 없는 자산은 **현장별 투입비 현황**(예상/확정 금액, 카테고리별 투입비, 결재·발주·운송·거래내역서 대기 건수)이다. 홈의 첫 문장을 "자재를 사면 현장 투입비가 저절로 정리된다"로 바꾸고, 상품은 그 약속을 실행하는 수단으로 배치한다.

### 2.2 세 축 분리

- **솔루션** — 공정·위험 상황(문제)이 제목. 자재 조합·규격·시공 유의사항이 답. 검색 유입과 상담의 진입점.
- **상품** — 규격·단가·재고로 고르는 카탈로그. 반복 구매·비교.
- **현장** — 로그인 후 업무 도구(발주서·투입비·거래내역·정산). 재방문과 고착.

카드 형태·색·정보 구성을 셋으로 분리한다. A1~AL 카테고리 색은 이미 현황 화면에 존재하므로 이를 사이트 전체 디자인 시스템의 뼈대로 승격한다.

### 2.3 로그인 벽 후퇴

솔루션·상품·검색·AI 질문은 비로그인 공개. 로그인은 담기 이후 발주·견적 직전에 요구. 가입 화면에 얻는 것 3줄 + 역할 선택(구매사/판매사)을 둔다.

## 4. 기술 개편

- **공개 페이지 분리 및 서버 렌더링** — 홈·솔루션·카테고리·상품 상세·판매사·소개/사례를 Next.js 등으로 분리해 정적/서버 렌더링. 색인과 첫 화면 지연이 동시에 해결됨. 로그인 이후 업무 화면은 기존 Meteor 앱 유지 후 점진 이관.
- **번들** — 2.7MB 단일 번들을 라우트 단위로 분할, 클라이언트에 불필요한 AWS SDK 전체 포함 제거, 폰트 1벌 서브셋. 목표: 첫 화면 전송 300KB 이하.
- **보안** — AWS 키 폐기·회전, presigned URL 업로드, 클라이언트 설정에서 비밀값 제거, AI API 운영 인스턴스 분리 및 서버 프록시화, nginx 보안 헤더 추가.
- **URL·색인** — 상태를 URL에 반영, 한글 경로 이중 인코딩 수정(또는 영문 slug), robots.txt·sitemap.xml 생성, canonical 지정(www/non-www 정리), 없는 주소는 실제 404 반환.
- **마크업** — 이동은 `<a href>`로(JS 클릭 병행), 페이지당 h1 하나, header/nav/main/footer 도입, 이미지 alt, `<html lang="ko">`.
- **이미지** — 상세 이미지 WebP 변환·리사이즈·지연 로드.
- **운영 규칙** — 빈 값이면 섹션 숨김, 상품명 내부 메모 금지, 상품 0개 판매사 비노출을 데이터 검증 규칙으로 고정.
